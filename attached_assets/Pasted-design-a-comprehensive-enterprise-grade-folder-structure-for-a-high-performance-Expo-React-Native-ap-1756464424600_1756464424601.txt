📋 Detailed Directory Explanations
1. Core Application Structure (src/)
src/app/ - Expo Router File-Based Routing
This follows Expo Router v3 conventions for file-based routing:

_layout.tsx: Root layout with providers and global navigation
(auth)/: Auth-protected route group
(tabs)/: Tab-based navigation group
Supports nested layouts and route groups for complex navigation
src/features/ - Feature-Based Architecture
Each feature is a self-contained module with its own:

Components: Feature-specific UI components
Hooks: Custom hooks for feature logic
Services: API calls and business logic
Store: State management (Redux slices)
Types: TypeScript definitions
Utils: Feature-specific utilities
Example Feature Structure:


// src/features/authentication/hooks/useAuth.ts
export const useAuth = () => {
  const dispatch = useAppDispatch();
  const { user, isLoading } = useAppSelector(authSelectors.selectAuth);
  
  const login = useCallback(async (credentials: LoginCredentials) => {
    return dispatch(authActions.login(credentials));
  }, [dispatch]);
  
  return { user, isLoading, login };
};
src/components/ - Reusable UI Components
Organized by component type and complexity:

ui/: Base design system components (Button, Input, Modal)
forms/: Form-specific composite components
navigation/: Navigation-related components
feedback/: Loading states, errors, empty states
2. Shared Resources (src/shared/)
src/shared/api/ - API Layer Architecture
Centralized API management with:

Clients: HTTP/GraphQL client configuration
Interceptors: Request/response middleware
Endpoints: API endpoint definitions

// src/shared/api/clients/httpClient.ts
import axios from 'axios';
import { authInterceptor } from '../interceptors';

export const httpClient = axios.create({
  baseURL: process.env.EXPO_PUBLIC_API_URL,
  timeout: 10000,
});

httpClient.interceptors.request.use(authInterceptor.request);
httpClient.interceptors.response.use(authInterceptor.response);
src/shared/utils/ - Utility Functions
Organized by functionality:

Formatters: Data formatting utilities
Validators: Input validation functions
Helpers: General-purpose utilities
3. State Management (src/store/)
Redux Toolkit Architecture
Slices: Feature-specific state slices
Middleware: Custom middleware for API calls, persistence
Selectors: Memoized state selectors

// src/store/store.ts
import { configureStore } from '@reduxjs/toolkit';
import { authSlice } from '../features/authentication/store';
import { apiMiddleware } from './middleware';

export const store = configureStore({
  reducer: {
    auth: authSlice.reducer,
    // Other feature slices
  },
  middleware: (getDefaultMiddleware) =>
    getDefaultMiddleware({
      serializableCheck: {
        ignoredActions: ['persist/PERSIST'],
      },
    }).concat(apiMiddleware),
});

🎯 Architecture Patterns & Best Practices
1. Feature-Based Organization
Each feature is completely self-contained, promoting:

Scalability: Teams can work independently on features
Maintainability: Clear boundaries and responsibilities
Testability: Isolated testing per feature
Code Splitting: Easy lazy loading of features
2. Naming Conventions
Files and Directories:
PascalCase: Components (UserProfile.tsx)
camelCase: Utilities, hooks (useUserProfile.ts)
kebab-case: Directories (user-profile/)
SCREAMING_SNAKE_CASE: Constants (API_ENDPOINTS.ts)

import { render } from '@testing-library/react-native';
import { Provider } from 'react-redux';
import { store } from '../../src/store';

export const renderWithProviders = (component: React.ReactElement) => {
  return render(
    <Provider store={store}>
      {component}
    </Provider>
  );
};
